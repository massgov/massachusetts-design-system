# Tokens v2.0.0 migration guide

This guide is primarily for consumers of MDS tokens code resources ([@massds/mds-tokens](https://www.npmjs.com/package/@massds/mds-tokens)) on V1 who want to learn about the changes between V1 and V2 ([see release notes](https://github.com/massgov/massachusetts-design-system/releases/tag/tokens-v2.0.0)) and navigate the breaking changes we introduced to the typography tokens. 

Previously, typography styles were exposed as composite CSS font shorthand tokens, such as:

```
--mds-text-heading-lg
--mds-text-body
--mds-text-body-bold
```

These shorthand tokens bundled font-family, font-weight, font-size, and line-height into a single value. That made the API compact, but also rigid and repetitive, especially when only one attribute, usually font size, changed across breakpoints or variants.

In version 2.0.0, typography tokens are now broken into longhand attribute tokens:

```
--mds-text-heading-font-family
--mds-text-heading-font-weight
--mds-text-heading-font-size-lg
--mds-text-heading-line-height-lg
--mds-text-body-font-family
--mds-text-body-font-weight
--mds-text-body-font-weight-bold
--mds-text-body-font-size
--mds-text-body-line-height
```

This is a breaking change. If your team references the old shorthand tokens, you’ll need to update those references when upgrading to v2.0.0.

## Why we made this change
This gives us a more stable and flexible typography foundation, and avoids resetting the other omitted attributes. Instead of redefining full shorthand values whenever one part of a text style changes, we can now update individual attributes independently.

## Migration example
Before:

```
.my-heading {
  font: var(--mds-text-heading-lg);
}
```

After:

```
.my-heading {
  font-family: var(--mds-text-heading-font-family);
  font-weight: var(--mds-text-heading-font-weight);
  font-size: var(--mds-text-heading-font-size-lg);
  line-height: var(--mds-text-heading-line-height-lg);
}
```

Alternatively, we recommend using @massds/mds-styles v1.1.0, which now composes these longhand tokens into .mds-text-* utility classes and Sass mixins.


```
<h2 class="mds-text-heading-lg">Section heading</h2>
```

Or in Sass:


```
@use "pkg:@massds/mds-styles/scss/mixins" as mixins;
.my-heading {
  @include mixins.text("heading-lg");
}
```

## Additional change
Eyebrow-specific casing and letter spacing are no longer published as token variables. These values now live in the styles layer, where they are applied by the eyebrow utility and mixin styles.

## Impact
This release improves long-term maintainability and makes typography tokens easier to evolve, but it is not backward compatible. Any code that references the old composite typography shorthand tokens will need to be updated when upgrading to v2.

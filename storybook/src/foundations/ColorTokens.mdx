# Color tokens

---

## Brand and utility colors

The design system separates **brand** colors from **utility** colors so each serves a distinct purpose.

Brand colors create a consistent visual identity for Commonwealth digital experiences. Utility colors communicate universally recognized meanings such as success, warning, danger, and information so people can quickly understand system status wherever it appears.

[Learn more about the design system brand and utility colors](https://www.mass.gov/info-details/colors).

---

## How to choose color tokens

Choose a token based on the role the color performs in the interface.

**Interactive** - Changes when someone interacts with an element  
**Content** - Helps people read, understand, and recognize information  
**Section** - Groups related content and creates visual hierarchy  
**Borders** - Separates content, organizes layouts, and communicates status  
**Focus** - Shows where keyboard focus is on the page  
**Surface** - Provides the default background for the experience  
**Base** - Supports light and dark themes with white, black, and inverse colors  
**Overlay** - Creates transparency and layered interface effects

---

## Interactive colors

Interactive color tokens define colors that change when someone interacts with an element.

Use them for buttons, links, icons, borders, and other interactive elements that respond to hover, focus, active, or disabled states.

Interactive colors are organized by visual emphasis - **lowest**, **low**, **mid**, **high**, and **highest** - instead of by component. This makes the tokens flexible, reusable, and consistent across the design system.

> **Rule of thumb**
>
> If the color changes when someone interacts with it, use an **interactive** token.

### Interactive brand

Use interactive brand colors for the majority of interactive elements.

**Usage examples include:**

- Filled button backgrounds
- Outline button borders, text, and icons
- Ghost button text and icons
- Inline links
- Single action interactive card borders
- Menu item hover and active state backgrounds

<ColorTokenTable tokens={tokenGroups.interactiveBrand} />

### Interactive utility

Use interactive utility colors only for destructive actions.

**Usage examples include:**

- Filled danger button backgrounds
- Outline danger button borders, text, and icons
- Ghost danger button text and icons
- Delete actions
- Remove actions

<ColorTokenTable tokens={tokenGroups.interactiveUtility} />

## Content colors

Content color tokens define the colors used for text and icons throughout the interface.

Use content colors whenever the color does not change because of interaction.

### Content brand

Use content brand colors for the majority of text and icons.

**Usage examples include:**

- Headings
- Body text
- Supporting text
- Decorative icons
- Navigation icons
- Disabled button labels
- Placeholder text

<ColorTokenTable tokens={tokenGroups.contentBrand} />

### Content utility

Use content utility colors to communicate status.

**Usage examples include:**

- Inline message icons
- Form input error messaging
- Password creation success messaging
- Badge labels

<ColorTokenTable tokens={tokenGroups.contentUtility} />

---

## Section

Section color tokens organize content and establish visual hierarchy by applying color to backgrounds across larger areas of a page.

### Section brand

Use section brand colors to reinforce the visual identity of the experience.

**Usage examples include:**

- Hero sections
- Landing page banners
- Featured content
- Content bands
- Alternate page sections

<ColorTokenTable tokens={tokenGroups.sectionBrand} />

### Section utility

Use section utility colors when an entire section background communicates system status.

**Usage examples include:**

- Success confirmation sections
- Warning callouts
- Danger summaries
- Informational notices

<ColorTokenTable tokens={tokenGroups.sectionUtility} />

---

## Surface

Surface color tokens define the default background for Commonwealth digital experiences.

The design system intentionally uses a single surface color to provide a consistent visual foundation across products and services. For light themes we use a slightly off-white color to reduce visual glare, improve reading comfort, and create a softer foundation for content.

**Usage examples include:**

- Page backgrounds
- Application backgrounds

<ColorTokenTable tokens={tokenGroups.surface} />

---

## Borders

Border color tokens separate content, organize layouts, reinforce hierarchy, and communicate status.

### Border brand

Use border brand colors for structure and decoration.

**Usage examples include:**

- Cards with multiple actions
- Panel borders
- Content wrappers
- Section dividers
- Table and list separators
- Decorative accents, such as a line beneath a heading
- Non-interactive step indicators

<ColorTokenTable tokens={tokenGroups.borderBrand} />

### Border utility

Use border utility colors when a border communicates status.

**Usage examples include:**

- Success messages
- Warning messages
- Danger messages
- Informational messages
- Validation containers

<ColorTokenTable tokens={tokenGroups.borderUtility} />

---

## Focus

Focus color tokens define the colors used to communicate keyboard focus throughout the interface.

We use one focus color for light backgrounds and one for dark backgrounds. This ensures focus indicators remain highly visible, consistent, and accessible across all components and themes.

<ColorTokenTable tokens={tokenGroups.focus} />

---

## Base

Base color token sets include **white**, **black**, and **inverse** values to support light and dark themes.

- Use **white** when the color should always be white
- Use **black** when the color should always be black
- Use **inverse** when the color should automatically switch between white and black based on the active theme

<ColorTokenTable tokens={tokenGroups.base} />

---

## Overlay

Overlay color tokens define colors with built-in opacity for creating layered interface effects.

**Usage examples include:**

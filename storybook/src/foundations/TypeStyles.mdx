# Type styles

Use type styles to establish hierarchy and make content easier to scan. Choose semantic HTML based on document structure, not visual size. Use the typography tokens and utility classes provided by the Massachusetts Design System to apply visual scale consistently.

---

## Noto Sans

Noto Sans is the primary typeface for Massachusetts Design System websites and digital applications. It provides clear, readable text across different screen sizes and supports a wide range of languages and characters.

If your digital experience cannot support Noto Sans, use the font fallback stack: `"Noto Sans", "Helvetica", "Arial", sans-serif`.

### Getting Noto Sans

Use Noto Sans in designs and local development environments.

For web projects, load Noto Sans using the approved project setup. For local development, use the available font files or install the package provided by the design system.

- Google Fonts: Embed it using `link` or `@import` rules, or download the static and variable font packages from the [Noto Sans family on Google Fonts](https://fonts.google.com/specimen/Noto+Sans).
- Package manager: Install font assets for web bundles through npm.

```bash
npm install @fontsource/noto-sans
```

## Type scale

Use the type scale to create a clear visual hierarchy between headings, body copy, labels, captions, and other text.

Choose a type style based on the role of the content, not only on the visual size you want. Keep semantic HTML separate from visual styling so people using assistive technology can navigate the content structure correctly.

### Using REM units for accessibility

Use `rem` units for typography when implementing the design system so text sizes can respond to the root font size.

## Headings

Headings divide pages into recognizable landmarks and sections. Use heading elements to reflect the structure of the content, then use type styles when the visual size needs to differ from the semantic level.

### Heading hierarchy

**Use semantic headings**

Use `h1` through `h6` based on the document hierarchy. Do not choose a heading level only because it has the visual size you need. Always descend sequentially (`h1` to `h2` to `h3`).

**Keep a single page title**

Use only one `h1` for the page's main topic. Use `h2` for major sections and `h3` for sections nested within an `h2`.

## Labels

Use labels to name controls, fields, navigation elements, and other interface elements.

**Usage examples include:**

- Text boxes and input fields, such as "First name" or "Email address"
- Buttons that identify an action, such as "Submit application" or "Save"
- Checkboxes and radio buttons that describe what someone can select
- Navigation and tab controls
- Table headers that identify columns

## Eyebrows

Use eyebrows to provide short context above a page or section title.

**Usage examples include:**

- Above a section title to identify a category before a reader moves into a new section
- Above a step or task to provide additional context

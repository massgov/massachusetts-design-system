# Massachusetts Design System

The Massachusetts Design System provides reusable components, design guidance, and implementation resources for creating consistent and accessible digital experiences across the Commonwealth.

Use the Design System as a starting point for new experiences, or adopt it progressively as you update existing products and services.

---

## Why use the Massachusetts Design System?

Starting with the Massachusetts Design System gives your team a shared foundation for design and development.

### Save time and effort

Use shared components, design tokens, and code resources instead of recreating common interface elements. Shared resources also make handoff between designers and developers easier.

### Create consistency and build trust

Use a common visual and interaction foundation to create more consistent and familiar experiences across Massachusetts services.

### Build with accessibility in mind

Start with tested components and established accessibility guidance rather than solving common accessibility challenges from scratch.

> ### Beta: Available now and continuing to evolve
>
> The Design System is in beta and ready to use. The components, design tokens, guidance, and code resources available today provide a strong foundation for teams starting new work or improving existing experiences.
>
> As the system matures, we expect mostly incremental improvements, such as code cleanup, minor visual or behavioral refinements, and clearer documentation and accessibility guidance. We'll document changes through versioning and a changelog so teams can confidently adopt updates when they are ready.

## Use the Design System progressively

The [Website Domain Policy](https://www.mass.gov/policy-advisory/website-domain-policy) sets requirements for constituent-facing digital experiences, including accessibility and design. The Massachusetts Design System provides shared components, patterns, and guidance to help teams meet those requirements and create more consistent experiences.

You do not need to adopt the entire Design System at once. Start with the resources that fit your project, platform, timeline, and stage of development.

Use shared components and guidance as you build new features, replace existing components, or make other improvements. For existing experiences, Design System tokens can also help you move toward the system's visual language without requiring a full redesign.

Design System tokens can be applied to values such as color, typography, spacing, corner radius, and elevation. This can be a practical way to improve visual consistency over time, particularly when replacing existing components is not feasible.

Guidance for applying tokens to specific platforms is still being developed. Contact the Design System team at <a href="mailto:designsystem@mass.gov" target="_blank" rel="noreferrer">{`designsystem@mass.gov`}</a> for help determining whether this approach can work for your project.

For new projects where your team controls the front-end experience, use the Design System as the recommended starting point.

Read the [Website Domain Policy](https://www.mass.gov/policy-advisory/website-domain-policy) for the full requirements and scope.

## What this means for your project

### If your project is already in progress

You do not need to stop work or redesign an established experience just to match the latest Design System resources.

Focus on meeting Commonwealth requirements for accessibility and constituent-facing design, and adopt Design System resources where they can be incorporated without significant rework.

As you add features, replace components, or make other improvements, look for opportunities to move closer to the Design System.

### If your project has already launched

You do not need to retrofit a live experience solely to match the latest Design System resources.

When you make updates, use them as opportunities to adopt Design System guidance and components that support your service and meet current requirements.

### If you are using a low-code or no-code platform

Use Design System guidance and visual direction where your platform allows it.

You do not need to recreate or override built-in platform behavior when doing so would introduce accessibility problems, significant maintenance work, or make future platform updates harder to manage.

Focus on the parts of the experience you can control, such as content, hierarchy, visual choices, and interaction patterns.

### If you are starting a new project

Use the Design System as the recommended starting point when your team controls the front-end experience.

Adopt the components and guidance your project can support while meeting Commonwealth accessibility and design requirements. If your platform, technology, staffing, or other constraints prevent full adoption, use the resources that provide the most value and look for opportunities to improve alignment over time.

## Design with the Figma libraries

Use the Massachusetts Design System Figma libraries alongside Storybook when designing digital experiences.

Figma is the preferred design source for working with shared styles, components, patterns, and templates. Storybook provides the corresponding guidance and implementation resources for coded components. Together, they give designers and developers a shared foundation for moving from design to implementation.

**The Figma libraries include:**

- Design tokens built with variables for shared values such as color, typography, spacing, corner radius, and elevation
- The full Design System component library
- Composed patterns for common interface needs
- Page templates that provide a starting point for common layouts and services

The variables in Figma correspond to the design tokens used in code. As coded components are completed, their Figma and Storybook versions are maintained in parity so designers and developers can work from the same component definitions.

Figma access is available to Massachusetts state agencies and vendor partners working with them. Because paid seats require an agency-supported access and chargeback process, visit [Designer resources for the Massachusetts Design System](https://www.mass.gov/info-details/designer-resources-for-the-massachusetts-design-system) to learn how to get started.

You can also [learn more about why the Commonwealth uses Figma](https://www.mass.gov/info-details/why-we-use-figma) as a shared design tool.

## Growing the component library

The Design System is still growing. Not every pattern or component teams need is available yet.

We are working toward a core library of approximately 40 components. Existing components will also continue to evolve as we learn from teams using them.

If the Design System does not yet cover your need, you do not need to wait for a new component before moving your project forward. Contact the Design System team or share feedback so we can help you evaluate your options and use what we learn to inform the system's roadmap.

## Get help and share feedback

If you have questions, need help applying the Design System, or run into a need that the current component library does not cover, contact the Design System team at <a href="mailto:designsystem@mass.gov">{`designsystem@mass.gov`}</a>.

Your questions and feedback help us understand where teams need more guidance and where the Design System should continue to grow.

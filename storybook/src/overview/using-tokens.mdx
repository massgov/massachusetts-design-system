# Using tokens

`@massds/mds-tokens` exposes shared design decisions as CSS custom properties. Use these values for color, typography, spacing, corner radius, elevation, and other styles in your own CSS.

You can adopt tokens independently, including in an existing application. The package supplies values; your CSS determines where they apply. It does not require the styles, assets, or components packages.

## Install and load tokens

<Source language="bash" code={installExample} />

Import the public semantic token entrypoint from your application's CSS entrypoint:

```css
@import "@massds/mds-tokens/dist/index.css";
```

Use `dist/index.css` for application styling and reference only semantic tokens in your application and component CSS. This entrypoint loads the primitive values needed by the semantic tokens automatically; do not import `dist/primitives.css` separately.

### Why reference semantic tokens?

Primitive tokens contain raw values, such as color hex codes, spacing lengths, and font sizes. Their names identify a value within a palette or scale, without specifying where it should be used. Semantic tokens assign those values to a purpose, such as default text color or body text size.

For example, the current default text color is defined through these two layers:

| Layer | Token | Meaning |
| --- | --- | --- |
| Primitive | `--mds-color-brand-gray-1300: #141414` | A raw color in the gray palette |
| Semantic | `--mds-content-brand-neutral-default: var(--mds-color-brand-gray-1300)` | The color to use for default neutral text content |

Reference `--mds-content-brand-neutral-default` in your CSS, as shown below. The semantic name expresses the design intent and lets the Design System change the underlying value or mapping without requiring you to replace primitive references throughout your application.

Although primitive variables are available after loading `index.css`, they are internal inputs to the semantic layer. Referencing them directly ties your styling to the current raw values and bypasses future updates to the semantic mapping. Choose the semantic token that matches the role of the element you are styling.

## Apply tokens in custom CSS

Reference a semantic token with `var()` inside a CSS declaration:

```css
.service-description {
  color: var(--mds-content-brand-neutral-default);
  font-family: var(--mds-text-body-font-family);
  font-size: var(--mds-text-body-font-size);
  font-weight: var(--mds-text-body-font-weight);
  line-height: var(--mds-text-body-line-height);
}
```

```html
<p class="service-description">Find services and information from the Commonwealth.</p>
```

Typography tokens expose individual attributes. For a complete shared text style, use a utility class such as `.mds-text-body` or the Sass `text("body")` mixin from [Using Styles](?path=/docs/overview-getting-started-using-styles--docs).

## Use tokens with styles and components

Load token CSS before utility or component CSS so their custom properties are available. Tokens are loaded separately; the styles and components packages do not bundle them.

See [Using Styles](?path=/docs/overview-getting-started-using-styles--docs) and [Using Components](?path=/docs/overview-getting-started-using-components--docs) for complete setup examples.

# Getting started

The Massachusetts Design System provides coded resources including shared design tokens, reusable styles, static assets, and standardized HTML markup and compiled CSS organized by component, to help state agencies implement consistent, accessible and maintainable user interfaces that match the design system.

The primary way to adopt coded components is to copy and paste the HTML and CSS snippets from Storybook into your project. Your implementation team chooses its frontend technology and adapts the markup into its own framework components or templates. The Design System does not prescribe a framework. See [Using Components](?path=/docs/overview-getting-started-using-components--docs) for the adoption workflow.

We also provide four npm packages—assets, tokens, styles, and an experimental distribution of component files. Adopt the packages that fit your project. 


## Choose your packages

| Package | What it provides | When to use it |
| --- | --- | --- |
| [`@massds/mds-tokens`](?path=/docs/overview-getting-started-using-tokens--docs) | Shared design values exposed as CSS custom properties | Apply design decisions such as color, spacing, and typography in your own CSS |
| [`@massds/mds-styles`](?path=/docs/overview-getting-started-using-styles--docs) | Common page layout styles and styles shared across components, available as utility classes and Sass mixins | Compose pages with layout and grid styles, or reuse shared styles such as typography and spacing across components |
| [`@massds/mds-assets`](?path=/docs/overview-getting-started-using-assets--docs) | Icons, state seals, and animation files | Use static assets independently or alongside components |
| [`@massds/mds-components`](?path=/docs/overview-getting-started-using-components--docs) | Experimental distribution of Twig templates, static HTML, and compiled component CSS | Access component files through npm as an alternative to copying Storybook snippets |

Tokens supply the values. The styles package builds on those values to provide layout styles outside individual components, such as page containers and grids, and shared styles used across components, such as typography and spacing. Use its utility classes to compose pages in HTML or its Sass mixins to incorporate shared styles into your own classes. Components use those mixins during their build to produce self-contained component CSS. Assets supply the visual files used by applications and components.

Tokens and assets can each be used independently. The styles package requires token CSS. Component CSS requires token CSS; its shared styles are already compiled in. Components that use icons or state seals depend on those assets. The snippets include icons as inline SVG and reference state seals through CDN URLs, so the asset dependency does not require installing the assets npm package. Install the styles package alongside components when you also want utility classes or Sass mixins.

## Start using the resources

Start with the component snippets, and install the supporting packages your application needs. These guides explain each resource and how to use it:

- [Using Tokens](?path=/docs/overview-getting-started-using-tokens--docs): load tokens and reference them in custom CSS.
- [Using Styles](?path=/docs/overview-getting-started-using-styles--docs): choose utility classes or Sass mixins and learn how foundation code tabs work.
- [Using Assets](?path=/docs/overview-getting-started-using-assets--docs): load icons, state seals, and animation files.
- [Using Components](?path=/docs/overview-getting-started-using-components--docs): copy HTML and CSS from Storybook, adapt them to your technology, or use the experimental package.
